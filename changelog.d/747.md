- Add `scan-export` (`seo_scan_export`): a read-only, offline scan-data export under the
  versioned `scan_export.v1` contract. It reads a validated `scan.v1` SQLite artifact or an SF
  Analyzer `audit.json` and writes CSV (one file per record type plus a manifest), XLSX
  (write-only workbook), a streaming JSON envelope, or a documented XML document. Each output
  carries provenance, exported row counts, run statistics, and explicit coverage — including
  which checks ran, were skipped, were disabled, or stayed unaccounted — none of which field
  selection can remove. `--records` and `--fields` provide validated projection across page,
  link and finding records; unknown record types or field names are rejected before any output
  file is created. Absent values stay explicit (JSON `null`, XML `state="absent"`, CSV/XLSX `\N`)
  rather than becoming fabricated zeros. XML output is generated serialization with correct
  UTF-8 escaping; it never parses caller-supplied XML, DTDs, stylesheets, or entities. CSV/XLSX
  keep the existing formula-injection defense; XLSX refuses Excel row/column/cell-text overflows
  instead of truncating, and any serialization failure leaves no plausible partial artifact.
